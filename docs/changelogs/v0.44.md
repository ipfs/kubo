### 🔦 Highlights

#### Fixed: API.HTTPHeaders.Access-Control-Allow-Headers now respected

Access-Control-Allow-Headers configured via API.HTTPHeaders was silently
ignored: the API always returned the default stream output headers
(X-Stream-Output, X-Chunked-Output, X-Content-Length) instead of the
user-configured value, causing browsers to reject cross-origin requests that
used allowed headers such as Authorization.

This is now fixed: the configured value is passed to the CORS middleware so it
appears in preflight (OPTIONS) responses, and the response emitter no longer
overwrites Access-Control-Allow-Headers with hardcoded stream output headers.
See [#9586](https://github.com/ipfs/kubo/issues/9586).

#### �️ Badger v1 datastore removed

The `badgerds` datastore and the `badgerds` / `badgerds-measure` profiles have
been removed. Badger v1 has not been maintained by its upstream maintainers for
years and had known bugs (startup timeouts, shutdown hangs, file descriptor
exhaustion). It was deprecated in [v0.40](v0.40.md#-badger-v1-datastore-slated-for-removal-this-year)
with a loud warning on every daemon start.

Kubo now refuses to start if it detects a `badgerds` datastore in the config
and prints migration instructions. To migrate, create a new `IPFS_PATH` with
`flatfs` (`ipfs init --profile=flatfs`), move pinned data via
`ipfs dag export/import` or `ipfs pin ls -t recursive|add`, and decommission
the old badger-based node. See [#11186](https://github.com/ipfs/kubo/issues/11186).

#### �📦️ Dependency updates

- update `go-ds-pebble` to [v0.5.13](https://github.com/ipfs/go-ds-pebble/releases/tag/v0.5.13)
- removed `go-ds-badger` (badger v1 datastore support, deprecated in v0.40)
