#### 🧭 Opt-in: restarts rejoin the DHT through known peers

With the new
[`Routing.PersistRoutingTable`](https://github.com/ipfs/kubo/blob/master/docs/config.md#routingpersistroutingtable)
option, Kubo saves its Amino DHT routing table to the repo after 10 minutes,
then every hour, and on shutdown. On the next start it reconnects to those
peers first, and contacts the
[`Bootstrap`](https://github.com/ipfs/kubo/blob/master/docs/config.md#bootstrap)
peers only if fewer than 10 of the saved peers answer within 20 seconds.
Restarts then depend less on the same small set of bootstrap peers, and a node
that knows the network can rejoin it even when those peers are unreachable. A
new node, which has no saved peers yet, still starts from the bootstrap peers.

Saved peers are checked like any other peer before they enter the routing
table, and a node with an empty `Bootstrap` list neither saves its routing
table nor dials saved peers. With the option on, startup no longer waits for a
first bootstrap round, and the snapshot replaces the backup bootstrap peers:
the list at `/local/temp_bootstrap_peers` is deleted on startup. With
[`Routing.AcceleratedDHTClient`](https://github.com/ipfs/kubo/blob/master/docs/config.md#routingaccelerateddhtclient),
the network crawls still start from the bootstrap peers. The snapshot is stored
in the repo datastore under `/kad-dht/routing-table/`.

To try it, run `ipfs config --json Routing.PersistRoutingTable true` and
restart the daemon.
