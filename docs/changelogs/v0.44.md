### 🔦 Highlights

#### `ipfs files rm` returns a proper error on failure

`ipfs files rm` now returns a real error when one or more paths cannot be removed, instead of writing the error as a regular output value. Over the RPC API (`/api/v0/files/rm`) this restores the `HTTP 500` status and the JSON error body (`{"Message":...,"Type":"error"}`), fixing a regression from v0.11 where failures were reported as `HTTP 200` with a plain, non-JSON string body. When several paths fail, all failures are reported. See [#8606](https://github.com/ipfs/kubo/issues/8606).
